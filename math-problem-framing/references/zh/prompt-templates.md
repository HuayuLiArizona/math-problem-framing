# Prompt 模板（按答案形态）

方括号 `[...]` 是要填的内容；用不到的段落直接删掉，不要留空壳。关键数学术语在中文后用括号保留英文原名。英文版模板见 `references/en/prompt-templates.md`。

## 目录

- T1 方法地图（两阶段的第一阶段：只分类、不求解）
- T2 推导 / 闭式解
- T3 证明或反驳某个性质
- T4 界 / 渐近阶 / scaling
- T5 建模选择
- T6 算法 / 数值方案
- T7 统计分析方案
- T8 审稿：检查一份已有推导
- T9 追问模板

---

## T1 方法地图

适用：入口 A（不知道是什么数学问题）。目的是让 LLM 帮用户看清"这个问题可以被形式化成哪几种数学问题、各自能回答什么"，然后由用户选择。不要让它在这一步求解。

```markdown
# 任务
我是[领域]研究者，不是数学家。下面描述一个我工作中遇到的问题。**先不要求解**，请帮我梳理它可以被形式化成哪些数学问题，方便我选择。

# 情况（用领域语言描述）
[3–10 行：系统是什么、观测到了什么、哪里让我困惑、什么决定依赖于这个答案。]
[如有，给一个带具体数字的小例子。]

# 我已知道 / 已尝试的
[已知结果、文献、失败的尝试。]

# 需要你做的
1. 用你自己的话复述问题，列出会改变数学表述的歧义。
2. 提出 2–4 种候选的数学形式化。每一种给出：
   - 数学对象（变量、空间、随机变量）和精确的问题；
   - 它依赖的关键假设，以及其中哪些在我的场景下最可疑；
   - 所属数学分支和标准方法名称（附英文原名）；
   - 它能给出什么形式的答案（闭式解、定性条件、界、数值流程），以及大致难度；
   - 1–3 个标准参考（教材章节或经典论文）。只引用你确定存在的文献。
3. 推荐先尝试哪一种并说明理由，列出我需要回答哪些问题才能在它们之间做选择。
```

## T2 推导 / 闭式解

```markdown
# 任务
在下面的模型和假设下推导[目标量 / 表达式]。如果不存在闭式解，请明确说明，并给出最好的替代形式（级数、注明适用范围的渐近近似 (asymptotic approximation)，或隐式方程加数值求解方法）。
推导之前，先复述问题并列出歧义；如果某个歧义会改变答案，说明你采用哪种解释。

# 背景
[≤5 行领域背景。形式化陈述以下文为准。]

# 记号与定义
[每个符号：类型、取值范围、单位、含义。]

# 模型
[方程 / 数据生成过程。]

# 假设
A1. …（本质假设）
A2. …（为可解性引入的简化——请说明放宽它时结果如何变化）

# 问题
[精确目标，例如"求 $t\ge 0$ 时 $C_{ss}(t)$ 的闭式表达式，作为 $D,\tau,k,V$ 的函数"。]

# 范围（不在问什么）
[不需要的内容，例如"不需要数值模拟；不讨论非线性药动学"。]

# 交付要求
- 逐步推导；标明每一步用到了哪条假设。
- 最终结果单独列一行，并写明适用范围。
- 如果结果只在特殊情形下成立，必须明确写出限制条件。

# 自检
- 把结果退化到[已知特例]，确认与[已知答案]一致。
- 检查单位 / 量纲。
- 检查极限：[参数 → 0，参数 → ∞]。
- 附一段简短的 Python（numpy/sympy/scipy）脚本，在[玩具实例]上数值验证公式。
```

## T3 证明或反驳某个性质

```markdown
# 任务
证明或反驳下面的命题。完整证明和严格反驳都算成功。如果命题按原文不成立、但在某个自然的附加假设下成立，请先给出反例，再陈述并证明修正后的版本。
开始之前，先复述命题并列出歧义。

# 记号与定义
[完整定义；量词写明；什么固定、什么变化。]

# 假设
A1. …

# 命题
[对所有 … 存在 … 使得 … 。常数可以依赖于[列表]，但不能依赖于[列表]。]

# 范围（不在问什么）
[相近但不在问的命题，例如"不是在问子列收敛"。]

# 什么算反例
[例如"给出具体的参数值和初始条件，并用计算或数值演示说明性质不成立"。]

# 交付要求
- 如果论证只在附加条件下成立（[线性 / 高斯 / 小步长 / d=1 …]），必须明确写出该限制，不得悄悄推广。
- 标出每条假设被用到的步骤。
- 引用的定理请给出名称和标准出处；不确定是否存在的结果不要使用。

# 方向（可选）
[可能的起点；已知的部分结果，以及它们**没有**覆盖什么。]
[可接受的阶段目标：… 的情形。阶段目标不能替代完整命题。]

# 自检
- 验证论证能还原[已知的简单情形]。
- 指出最薄弱的一步，以及你对它的把握程度。
```

## T4 界 / 渐近阶 / scaling

```markdown
# 任务
确定[量 Q]在下述范围内如何随[参数]变化。尽可能给出上界和下界，并说明界是否紧 (tight)。

# 记号与定义
[...]

# 范围设定 (regime)
[哪些参数趋于什么极限、相对速率如何、哪些保持不变。多个极限时写明极限次序。]

# 问题
[例如"求指数 a, b，使得当 $n\to\infty$ 且 $d/n\to\gamma\in(0,1)$ 固定时 $Q = \Theta(n^{a} d^{b})$"。说明常数是否重要。]

# 交付要求
- scaling law，并写明隐藏常数依赖于什么。
- 用一段话说明机制（为什么是这个阶）。
- 这个界在哪里失效。

# 自检
- 用启发式论证或量纲分析交叉检验。
- 给出检验预测指数的模拟设计（规模、重复次数）并附代码。
```

## T5 建模选择

```markdown
# 任务
帮我为[现象]选择数学模型。按下列准则比较候选模型（如有明显更好的可以补充），然后推荐一个。

# 情况与数据
[测量什么、多频繁、噪声水平、样本量、需要预测或解释什么。]

# 候选模型
M1. [方程]
M2. [方程]

# 比较准则
[例如能否复现[某特征]、参数能否由现有数据辨识 (identifiability)、可解释性、计算成本。]

# 交付要求
- 比较表：模型 × 准则，每格一句理由。
- 在每个模型下，哪些参数可以由我的数据辨识。
- 推荐的模型，以及一个能证伪它的具体检验（数据模式或实验）。
```

## T6 算法 / 数值方案

```markdown
# 任务
设计一个用于[计算/求解 …]的算法或数值方法，并论证其正确性。

# 输入 / 输出
[精确的输入格式、规模、所需精度、时间/内存预算。]

# 问题
[算法必须解决的精确数学问题。]

# 要求
- 在给定假设下的正确性论证（或带收敛速率的收敛性证明）。
- 以 [n, d, ε] 表示的复杂度。
- 失效模式：何时不稳定或很慢（刚性 (stiffness)、病态 (ill-conditioning)、非凸）。

# 交付要求
- 伪代码，以及用[语言]写的参考实现。
- 在答案已知的[玩具实例]上测试：[预期答案]。
```

## T7 统计分析方案

适用：医学、生物、心理等用数据回答问题的场景。核心是先写清**估计目标 (estimand)** 和**识别假设 (identification assumptions)**，再谈方法。

```markdown
# 任务
为下述数据提出估计[效应]的统计分析方案，并说明在什么假设下估计值具有因果 / 无偏的解释。

# 数据
[设计（RCT / 队列 / 病例对照 / 重复测量）、样本量、变量及其类型、缺失情况、处理或暴露是如何分配的。]

# 估计目标 (estimand)
[例如"在[哪类人群]中，[结局]在 30 天时的平均处理效应 (ATE)"——绝对尺度还是相对尺度。]

# 假定的因果结构
[已知或怀疑的混杂因素、中介变量、对撞因子 (collider)；如可能，给出文字版 DAG。]

# 交付要求
- 主分析方法及精确的模型设定。
- 识别假设（如无未测混杂、正性 (positivity)、一致性 (consistency)）以及如何检验每一条。
- 敏感性分析（如 E-value、替代的调整变量集）。
- 样本量 / 功效计算，所有输入写明；标出必须由我提供的输入。
- 这个设计**不能**回答什么。
```

## T8 审稿：检查一份已有推导

适用：入口 D。最好交给另一个模型或开一个新对话，避免同一上下文里"自己审自己"。

```markdown
# 任务
你是一位严格的审稿人。下面是一个问题陈述和另一个 AI 给出的解答。你的任务是找错，而不是附和。

# 问题陈述
[粘贴形式化问题。]

# 待审解答
[粘贴解答。]

# 审稿要求
1. 检查解答回答的是所陈述的问题，而不是一个更容易的相邻问题（例如特例、更弱的命题、不同的量词）。
2. 逐步检查，每一步标记：正确 / 有缺口（需要补论证）/ 错误，并简短引用该步。
3. 列出解答用到、但问题陈述中**没有**的所有假设。
4. 核对引用的定理：是否存在？其前提条件在这里是否真的满足？
5. 在[特例 / 数值实例]上检验最终结果并报告。
6. 结论：正确 / 正确但有缺口 / 错误。若错误，指出第一个致命错误。
```

## T9 追问模板

- **追问最弱一步**："你说第 [k] 步最薄弱。请把它展开成完整论证，每个不等式都给出理由；做不到就说清楚缺什么。"
- **放宽假设**："如果去掉假设 A[j]，哪些结论仍然成立？对每个不再成立的结论给出反例。"
- **要验算代码**："写一个自包含的 Python 脚本，在[实例]上数值检验[结果]，并打印偏差。"
- **换个角度**："用另一种方法（[替代方法]）重新求解同一问题，并与之前的答案比较。"
- **用领域语言解释**："用不超过 200 字，向一位只有本科数学基础的[领域]研究者解释这个结果和它的假设，包括什么情况下**不应**使用它。"
